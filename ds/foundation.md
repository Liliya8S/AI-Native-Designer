# Foundation

**Бриф:** Edtech, b2c, мобильное приложение, тон «дружелюбный, простой», локаль ru.

> Платформа mobile → минимальная высота тач-таргетов (кнопки, инпуты, иконки-кнопки) — 44pt. Учитывается при отрисовке компонентов в Фазе 3.

- scrim-20 = rgba(0,0,0,0.2), scrim-40 = rgba(0,0,0,0.4), scrim-60 = rgba(0,0,0,0.6) ← прозрачные, затемнение фона под модалками/оверлеями

- overlay-white-06 = rgba(255,255,255,0.06), overlay-white-12 = rgba(255,255,255,0.12), overlay-white-14 = rgba(255,255,255,0.14), overlay-white-55 = rgba(255,255,255,0.55), overlay-white-70 = rgba(255,255,255,0.7), overlay-white-72 = rgba(255,255,255,0.72) ← прозрачные белые оверлеи для UI-элементов поверх фото/видео на тёмных AR/камера-экранах (IconButton surface=translucent, ModePill, CaptureBar thumb/redo, DetectionBox, ScanFrame corners, AudioScrubber). Добавлены по итогам аудита: эти 28+ мест в Figma и коде годами держали белый цвет с прозрачностью прямо в fill/stroke-opacity, без единой переменной — по образцу scrim-* (чёрный оверлей), только белый. Заведены как отдельные ступени, а не одна alpha-переменная, т.к. в макете 6 разных процентов прозрачности используются для 6 разных ролей (тонкая заливка детекции / поверхность кнопки / миниатюра-заглушка / обводка гайда / текст неактивного состояния / фон плеера) — не вариации одного и того же элемента. Отрисованы свотчами на самой странице Foundation (ряд «Transparent», рядом с scrim-*/success-a12 и т.д.) — та же вёрстка (64×64, radius-8, подпись «имя · X%»), row/секция авто-растут (Auto Layout), соседние колонки Typography/Radii/Spacing просто сдвинулись правее, наложений нет.

### Радиусы
- **Figma (не менялась за всю сессию):** radius-none = 0, radius-sm = 4, radius-md = 8, radius-md-lg = 12, radius-lg = 16, radius-xl = 24 ← radius-md-lg добавлен по правке пользователя: у Button радиус Size=lg (16/52≈0.31) был непропорционально крупнее радиуса Size=md (8/44≈0.18) — заметно на глаз при сравнении кнопок разных размеров рядом. radius-md-lg=12 — компромисс между точной пропорцией (~13.5) и шагом сетки, используется только для Button Size=md. radius-xl добавлен для крупных карточек/контейнеров (взято из эксплорейшна «Тёрн 2»).
- **React-прототип, хронология правок (Figma ни разу не трогали — единая точка правки `src/tokens/primitives.css`, компоненты уже ссылались на `var(--radius-*)`, поэтому каждая правка одной строкой каскадом применялась ко всем карточкам/кнопкам/инпутам разом):**
  1. Сначала все 5 радиусов обнулили до `0px` — по запросу «во всех компонентах скругление 0px».
  2. Острые углы показались слишком резкими — смягчили до компактной шкалы `sm`=4px/`md`=6px/`md-lg`=6px/`lg`=8px/`xl`=8px (в диапазоне «4–8px», который просил пользователь, не возвращаясь к исходной Figma-шкале).
  3. **Текущее состояние:** скругления увеличены вдвое от компактной шкалы — `radius-sm`=8px, `radius-md`=12px, `radius-md-lg`=12px, `radius-lg`=16px, `radius-xl`=20px. Фон экрана — `surface-subtle` (#F9FAFB) на всех экранах, кроме тёмных AR-экранов.
  - Ни на одном из трёх шагов не трогали `border-radius: 50%`/`999px` (аватары, кнопки-иконки, пилюли-бейджи, чипы, кнопка-затвор камеры, OS-хром статус-бара) — это не «скругление угла» прямоугольника, а самостоятельная круглая/pill-форма.
- **Экраны, пересобранные «один в один» по визуальным референсам (главный экран, результат распознавания) используют свои литеральные px-значения радиуса прямо в CSS компонента, а не токены ДС** — см. `home-extended.md`/`recognition-result-text-first.md`. Это осознанное исключение (копирование референса), а не несинхронизированный токен — не путать со шкалой выше.

## Аудит страницы Foundation (screens_import_9)

Проверка витрины токенов в Figma (страница «Foundation», секция с сэмплами) против реального набора Variables — обнаружено расхождение: все токены, добавленные после исходного `ds_baseline` (расширения `component_variants`, «Тёрн 2», и этот прогон), существовали как Variables и использовались в компонентах/экранах, но не были отражены сэмплами на самой странице Foundation. Добавлены недостающие сэмплы:
- `Radii`: `radius-xl` (было только none/sm/md/lg)
- `Palette`: новая строка «Category» (`category-red-500`, `category-blue-500`), `category-red-a12`/`category-blue-a12` в строку Transparent
- `Semantic → Surfaces`: `surface-inverse`, `surface-well`
- `Semantic → Text`: `text-success`
- `Semantic → Borders`: `border-focus-ring`, `border-decorative`
- `Semantic`: новая строка «Category» (`bg-category-red`, `bg-category-blue`, `bg-category-red-subtle`, `bg-category-blue-subtle`, `text-category-red`, `text-category-blue`)

Также при этом починен баг на инстансе Badge `Variant=accent` в UI-ките — текст «Сегодня» рендерился чёрным на чёрном фоне при просмотре самого мастер-компонента изолированно (на реальных экранах текст был читаемым за счёт корректного резолва переменной в контексте использования). Причина — `setBoundVariableForPaint` не всегда синхронизирует литеральный fallback-цвет с фактическим значением переменной при первом биндинге. Пофикшено прямой установкой `fills` с явным литералом + alias одновременно.
